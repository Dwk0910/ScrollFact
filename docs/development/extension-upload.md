# 1단계: 확장 프로그램과 페이지 전송

이번 단계는 확장 패널 → 현재 페이지 HTML 캡처 → gzip 업로드 → 서버 문단 추출 → 원문 위치 연결이다. AI 요약·5분류 판단·전체 의견 게이지의 실제 데이터 연결은 다음 단계다. 과거 점수 API를 새로운 분석 계약으로 사용하지 않는다.

## 실행

1. 프로젝트 루트에서 `./gradlew :backend:bootRun` (Windows: `.\gradlew.bat :backend:bootRun`). 기본 서버는 `http://127.0.0.1:8080`이다.
2. `frontend`에서 `npm ci`, `npm run build`, `npm run check:extension`을 실행한다.
3. Chrome/웨일의 확장 관리 화면에서 개발자 모드를 켜고 `frontend/dist`를 압축 해제된 확장으로 불러온다. 기존에 설치했다면 확장을 새로고침한 뒤 원문 탭도 새로고침한다.
4. 일반 HTTP/HTTPS 페이지에서 확장 아이콘을 누른다. `현재 페이지 보내기`를 누르면 현재 URL·제목·HTML을 서버로 전송한다. 서버가 다른 컴퓨터에서 실행 중이면 `서버 연결`에서 주소를 바꾼다. 이 설정은 현재 패널을 닫으면 초기화된다.
5. 서버 수신 완료와 문단 수를 확인하고, 원문 스크롤·이전/다음 문단·원문 위치 버튼을 확인한다.

`reader.html`을 일반 브라우저에서 열면 화면을 볼 수 있지만 전송은 비활성화된다. 기존 실험 화면과 `src/sidepanel/`은 보존했다. 기본 확장 진입점만 새 리더로 전환했다.

## 전송과 현재 제한

- 자동 전송하지 않는다. 클릭 시 DOM을 복제하고 확장 자체 UI, 스크립트·스타일 본문, 폼 값, 편집 중인 텍스트, hidden/aria-hidden 텍스트를 제외한다. 원본 페이지를 수정하지 않는다. 전체 개인정보 제거를 보장하는 필터는 아니다.
- DOM 요소 구조를 유지해 서버의 선택자가 원문 위치와 일치하도록 한다. 서버 문단의 텍스트가 현재 원문과 다르면 해당 위치를 연결하지 않는다.
- 현재 `mode: diagnostic`으로 기존 API를 재사용한다. HTML 20 MiB/압축 5 MiB, 문단 200개/텍스트 20만 자 등의 기존 서버 상한을 유지한다.
- 서버는 사이트 전용 분기 없이 표준 articleBody/article/main 영역을 우선 찾고 그 안의 p/li/blockquote 및 출처 링크를 추출한다. 의미 있는 본문 영역이 없으면 기존 전체 문서 방식과 상한을 유지한다. 본문과 댓글의 의미 구분, div 중심 기사, iframe 내부 댓글, 아직 로드되지 않은 댓글, 웹 검색은 이번 구현에 포함되지 않는다. 출처 수집도 기존 서버 동작이므로 전송 후 대기 시간이 생길 수 있다.
- 문단 원문만 반환된다. 이를 해설이나 AI 판정으로 표시하지 않는다. 의견 영역은 분석 대기 상태이며 게이지 숫자와 사람들의 이유를 만들어 넣지 않는다.
- 다음 단계: 본문/의견 추출 계약 구체화 → AI의 문단 해설·문장별 5분류·전체 의견 묶음 반환 → 실제 원문 근거와 연결해 표시. 다섯 분류 중 ‘근거가 엇갈림’ 정의는 아직 사용자 검토가 필요하다.

## 검증

`npm run lint`, `npm run build`, `npm run check:extension`, `npm run test:api`.

브라우저 통합 검사는 `npm run test:reader`. 빌드 파일을 5173에서 제공하고 백엔드를 8080에서 실행해야 한다. Playwright가 설치되어 있어야 하며 필요하면 `SCROLLFACT_PLAYWRIGHT_MODULE`에 설치된 Playwright 모듈의 절대 경로를 지정한다. `SCROLLFACT_BROWSER_PATH`는 테스트용 Chrome 실행 파일, `SCROLLFACT_SCREENSHOT`은 선택적 캡처 경로다.

검사는 실제 콘텐츠 컨트롤러와 패널을 브라우저에 띄우고 Chrome 메시지 전달만 테스트 브리지로 대체한다. 실제 로컬 서버 업로드·문단 반환·한글 보존·원문 이동·입력값 제외·원문 불일치 거절·본문 변경 시 초기화를 검증한다. 설치된 확장 환경에서의 직접 확인과 임의 뉴스 사이트의 추출 품질 검증은 별도다.

관련 기사 후보는 반복 제목 링크와 날짜 구조로 분리한다. 인용·일반 목록은 유지하지만 의미를 확정하는 분류기는 아니므로 신문사 AI 요약 등 부가정보가 남을 수 있다. 직접 선택한 문단 강조는 원문에서 사용자가 다시 스크롤 조작할 때까지 유지한다.

## 실제 설치된 확장 검사

`node frontend/tests/reader-native.mjs`는 임시 브라우저 프로필에 `frontend/dist`를 실제 확장으로 로드한다. `SCROLLFACT_PLAYWRIGHT_MODULE`, `SCROLLFACT_BROWSER_PATH`(확장 로딩을 지원하는 Whale 등), `SCROLLFACT_ARTICLE_URL`을 지정한다. 선택적으로 `SCROLLFACT_TARGET_PASSAGE`(기본 10), `SCROLLFACT_SCREENSHOT`을 지정한다. 기본 주소의 서버가 실행 중이어야 한다. 테스트는 지정한 공개 기사로 이동해 실제로 업로드하고, 패널 버튼으로 대상 문단까지 이동하면서 원문 텍스트·강조를 대조한다. 마지막에는 로컬 DOM에서 선택 문단을 같은 텍스트의 새 요소로 교체해 강조 복원을 검사한다. 임시 프로필은 검사 종료 시 삭제한다.
