## 2026-11-24 Gemini 503 제한 재시도

## 왜 방향이 바뀌었나

원래 구상은 페이지 HTML을 서버에 보내 문단별 요약·신뢰도·근거·반대 주장을 스크롤로 읽는 것이었다. 긍정 점수, 음수 감점, 점수 없는 근거 리더 등 여러 실험을 했다. 사용자는 점수 차이의 의미를 설명하기 어렵고 AI가 정답을 단정하는 인상을 줄 수 있다는 멘토 피드백을 전했다. 과거 점수판은 비교용으로 남아 있으며 최신 방향의 확정안이 아니다.

또한 사실을 더 정확히 아는 것만으로 갈등이 줄어드는가에 대한 질문이 반복되었다. 특히 **사실에는 동의하지만 가치관·우선순위가 달라 갈등하는 경우**가 핵심 문제로 제기되었다. 따라서 상대가 중요하게 여기는 가치와 이유, 각 선택이 사람들에게 주는 부담, 공통점과 남은 차이를 읽도록 돕는 방향을 검토했다.

이는 아직 효과가 입증된 결과가 아니다. 실제 발언에서 확인되는 이유만 연결하고, 밝히지 않은 의도·양보 조건을 만들어내지 않는다. ‘반대 댓글 없음’을 ‘모두 동의함’으로 바꾸지 않고, 공감 수를 진실의 등급으로 취급하지 않는다. 건강한 소통을 의견 일치로 정의하지 않는다.

## AI와 백엔드의 정확한 상태

HTML gzip 업로드, 문단 파싱, 공개 출처 수집, 작업 상태·결과 조회, 취소·SQLite 저장은 구현되어 있다. `diagnostic` 모드는 AI 없이 연결을 점검한다.

실제 요약·점수 평가 제공자는 미설정이다. 기본 분석 모드는 제공자가 없으면 `503 evaluator_unconfigured`를 반환한다. `AnalysisEvaluator` 구현 또는 HTTP 어댑터가 필요하다. `SCROLLFACT_EVALUATOR_URL`은 OpenAI/Gemini 원래 API URL을 그대로 넣는 칸이 아니라 **저장소의 계약을 구현한 별도 어댑터 URL**이다.

festival 의견 수집·요약 API는 이 기존 분석 계약과 아직 통합하지 않았다. 최신 제품 방향을 구현할 때 계약·데이터 모델을 검토해야 하며 단순히 키만 넣으면 완성되는 상태가 아니다. 프론트 `VITE_*` 값에는 비밀키를 넣지 않는다.

## 실행과 이어가기

Windows PowerShell 설정과 명령은 루트 `README.md`를 따른다. 먼저 `npm ci` 후 `/festival.html`을 열어 현재 범위를 파악한다. Node.js 24.x를 기준으로 안내하며 백엔드는 JDK 17 이상이 필요하다.

일반 프론트 개발 포트는 5173, 백엔드는 8080이다. 과거 채팅의 8765 정적 서버는 자동 실행되지 않는다. `coaching.html`에 포함된 연결 점검은 8081 전용 설정이므로 일반 `/integration.html`의 8080과 구분한다. 이전 Mac의 절대 경로·실행 중 서버·로컬 DB는 새 컴퓨터에 생기지 않는다.

자료를 읽은 뒤 최신 방향과 미완료 범위를 짧게 요약하고 사용자의 다음 요청에 맞춰 작업한다. 과거 코칭 문서의 비교 시험안이나 AI의 제안을 현재 합의된 일정·검증 결과로 해석하지 않는다.

## 이번 이전 작업의 검증 기록

2026-11-19 Mac, Node.js 24.15.0, JDK 23.0.1에서 확인. Windows 실기 실행을 확인한 것은 아니다.

- 프론트 production 빌드와 확장 산출물 검사 통과.
- API 클라이언트 7개, 댓글 맥락 6개 테스트 통과.
- 백엔드 `:backend:test :backend:bootJar` 통과. Gradle 10 관련 기존 deprecated 경고 있음.
- 린트에서 festival 컴포넌트의 export 누락 1건 발견, 기본 export로 수정 후 린트·빌드·확장 검사를 다시 통과.
- 이번 업로드 준비에서는 브라우저 동작을 새로 검증하지 않았다. 이전 관련 채팅에는 패널 열기·닫기·선택 유지·원문 이동 확인 보고가 있다.

이 문서는 관련 채팅 ‘작업 이어가기’, ‘Summarize past work’, ‘ScrollFact 프론트엔드 분석’의 최근 요청·결과와 현행 파일을 기반으로 작성했다. 모든 채팅 원문·도구 로그·내부 추론을 GitHub에 게시한 것은 아니다.

- 같은 날 추가: 검토 HTML에서 수동 핵심 구절 표시 스크립트와 전환 UI를 제거했다. 이제 모든 자료 없음 구절에 얇은 노란 밑줄이 적용된다. 과거 스크린샷은 이전 상태다. 다섯 분류 전체의 새 시각 체계는 아직 제안 단계다.

## 2026-11-23 포스터 에셋만 전달

사용자는 포스터를 직접 조립하기로 변경했다. 추가 PPT 제작 대신 기능 화면 정확히 2장(글 맥락 분석, 관점 파악)과 배경만 `output/poster-assets-2026-11-23/ScrollFact-poster-assets.zip`으로 제공한다. 기능 화면은 검토 HTML에서 강조 테두리를 넣어 캡처했다. 배경은 원본 추출이 아니라 기존 포스터 색감 재현이며 JPG/SVG를 함께 제공한다.

- 에셋 v2: 사용자가 전체 화면에서 기능이 작고 테두리만으로 설명 표시가 불분명하다고 지적했다. `output/poster-assets-2026-11-23/v2/`에 실제 DOM의 기능 부분을 확대 발췌한 2장과 ZIP 제공. 주황 번호·화살표·의견 구절 강조를 포스터용 설명으로 명시했다. 서비스 구현 변경은 없다.

- 중요 정정: 사용자는 v2의 DOM 발췌·재배치를 UI 임의 변경으로 거절했다. 앞으로 기능 사진은 실제 화면의 연속된 캡처 영역을 자르거나 비례 확대하고 바깥 주석만 추가한다. v3/ScrollFact-real-screen-assets.zip이 이를 반영한 교체 에셋이다. v2는 사용하지 않는다.

- 인쇄용 후속 에셋: 기존 JPG 확대의 흐림을 해결하기 위해 `output/poster-assets-2026-11-23/print/`에서 원본 HTML을 iframe으로 실제 렌더링하고 연속 패널 영역을 클리핑했다(UI 내부 재배치 없음). 두 PNG 4320×3000, 로컬 PPT 6번 이미지 칸 비율 1.44:1. 첫 사진은 실제 기사 분석 패널의 해설/재확인/선택 문단, 두 번째는 전체 의견 게이지/펼친 발언/원문 링크. `ScrollFact-section6-print.zip` 전달.
