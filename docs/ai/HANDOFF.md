# ScrollFact AI 인수인계

## 2026-11-24 OpenAI 리더 연결과 시작·설정 UI

사용자가 OpenAI API를 선택했다. `mode: reader`와 Responses API 구조화 출력으로 본문/발언/부가정보 분류, 문단 해설, 5분류, 실제 인용 기반 관점 묶음을 연결했다. 원문 ID·인용·출처를 검증하고 원래 DOM 선택자를 유지한다. 부가정보는 패널에서 제외하되 DOM 문단 병합/분할은 아직 하지 않는다. 외부 검색과 별도 댓글 수집, 원문 문장별 5색 표시 및 해설 내부 밑줄은 후속이다. 과거 점수 API와 diagnostic 전송 점검은 보존한다.

기본 패널은 48px 고정 로고 헤더·설정, 중앙 안내/분석 버튼, ScrollFact란? 소개로 변경했다. 결과는 전체 의견과 현재 문단으로 표시한다. 의견 게이지는 반환된 발언 수이며 여론조사가 아니다. 설정은 서버 연결 상태, 원문 따라가기, 서버 주소/실행 모드이며 키는 서버 환경변수에만 둔다. 연결 확인은 설정 존재만 확인하며 API 키 유효성은 실제 분석 시 확인한다.

실행: `bash scripts/start-openai-server.sh` 또는 Windows `scripts/start-openai-server.ps1`. 자세한 내용은 `docs/development/openai-reader.md`. 실제 개발 환경에 키·모델이 없어 **실제 OpenAI 호출 및 분석 품질은 미검증**이다. 로컬 가짜 OpenAI HTTP 계약과 서버 통합 검사는 통과했다. 백엔드 28개 중 27개 통과·선택적 기사 fixture 검사 1개 생략, bootJar 성공. 프론트 lint/build/check:extension/API 8개 통과. 실제 Whale 설치 확장에서 시작·소개·설정·전송 점검·10번 문단 이동·DOM 교체 후 강조 복원을 확인했다. Windows 실행 스크립트는 Windows에서 미검증. 화면 캡처는 `output/reader-ai-2026-11-24/`에 있다.

## 2026-11-24 실제 Whale 확장 검증과 재렌더링 강조 복원

사용자가 문제 문단 번호를 11→10으로 정정했다. 첨부 HTML은 패널이며 12개 문단 수신/8번 표시 상태다. 실제 Whale 임시 프로필에 dist 확장을 설치하고 같은 공개 기사로 접속해 10번(결선 커넥트데이 문단)까지 패널 버튼으로 이동했다. 통상 선택은 정상이며 사용자의 지속 현상은 아직 동일 재현되지 않았다. 다만 선택한 문단을 동일 텍스트의 새 DOM 요소로 교체하면 하이라이트가 사라지는 프론트 버그를 별도로 재현했다. 선택 고정 상태에서 새 요소에도 activate를 적용하도록 수정, 설치된 확장으로 원문 대조 및 교체 후 복원 통과. 린트/빌드/확장 검사 통과. `frontend/tests/reader-native.mjs`로 재실행 가능, `docs/development/extension-upload.md` 참고. 사용자 환경 원인 확정/전체 해결로 단정하지 않는다.


## 2026-11-24 범용 추출 및 직접 선택 하이라이트 보완

사용자가 사이트별 하드코딩을 지적했다. 앞선 뉴스핌 도메인/#news-contents 전용 분기를 제거했다. 본문 후보는 표준 articleBody/article/main 구조로 찾는다. 관련 기사 후보는 3개 이상 반복되는 단일 제목 링크·서로 다른 목적지·높은 링크 텍스트 비율·별도 날짜 표시를 함께 요구하며 일반 인용/목록 및 표준 bibliography 역할은 보존한다. 단정하기 어려운 목록을 무조건 제거하지 않는다. 뉴스핌의 AI 요약·안내는 현재 본문 후보에 남아 내려받은 원문 기준 12개 블록(1,403자)이 반환된다. 이는 확정된 의미 문단 분리가 아니며 다음 AI 처리 단계에서 본문/부가정보 구분이 필요하다. 원문 DOM/선택자는 보존한다.

직접 문단 선택 시 스크롤 이벤트에만 의존하던 강조를 즉시 적용하도록 수정했다. 선택 상태는 원문 영역의 wheel/touch/pointer/스크롤 키 입력까지 유지하고 이후 자동 추적을 재개한다. 짧은 13개 문단의 11번을 페이지 하단에서 반복 선택하는 브라우저 회귀 검사와 수동 스크롤 복귀를 통과했다. 프론트 lint/build/check:extension, 백엔드 23개 테스트 및 bootJar 통과. 사용자의 11번 실제 원문 DOM은 첨부되지 않았으며(첨부는 패널 HTML), 동일 조건 합성 화면으로 검증했다. 적용 시 서버 재시작 + 확장 새로고침 + 원문 탭 새로고침이 필요하다.


## 2026-11-24 짧은 기사 문단 상한 오류 수정

뉴스핌 기사 `/news/view/20261102000423`에서 페이지 전체의 메뉴·관련 목록까지 수집해 상한 오류가 발생했다. 내려받은 HTML 기준 후보 384개, 실제 `#news-contents` 본문은 8문단·1,278자였다. 서버 HtmlParser는 뉴스핌 본문 영역, 일반 articleBody/article/main 영역 순으로 추출 범위를 정하고 출처 링크도 같은 범위로 제한한다. DOM을 변경하지 않아 원문 선택자를 보존한다. 본문 자체의 200문단·20만 자 상한은 유지한다. 실제 기사와 합성 회귀 사례를 포함한 백엔드 테스트 20개 및 bootJar 통과. 모든 사이트의 본문 식별을 보장하지 않으며 댓글의 별도 추출은 후속 작업이다. 서버 재시작 후 적용되고 확장 재빌드는 필요 없다.


## 2026-11-24 실제 확장 1단계 — 최신 구현 범위

사용자는 ① 확장 형태 정리·서버로 페이지 전송 ② 서버 AI 처리·반환 ③ 프론트 결과 연결 순서로 개발하기로 했다. 이번 범위는 ①이다. `frontend/reader.html`, `src/reader/`를 기본 확장 진입점으로 만들고 기존 diagnostic API로 실제 HTML 업로드·문단 추출·원문 추적을 연결했다. 전체 의견과 현재 문단의 두 영역을 유지하되 미구현 해설·게이지는 분석 대기로 표시한다. 본문/댓글 구분 및 AI 5분류 계약은 후속 작업이다. 설치·제약·검증은 `docs/development/extension-upload.md` 참고.

린트·빌드·확장 검사·API 7개 테스트 통과. 실제 로컬 서버와 브라우저에서 업로드·문단 이동·한글 보존·폼/스크립트 제외·원문 변경 시 초기화를 확인했다. 브라우저 테스트에서는 Chrome 메시지만 브리지로 대체했고 설치된 확장 직접 검증은 하지 않았다. 사용자 요청 브랜치는 `Development`, PR 제목은 `Framing basic service`다. 이전 포스터 파일은 이번 코드 커밋 대상이 아니다.


갱신: 2026-11-19 (한국시간). 저장소 코드, 프로젝트 문서 및 관련 Codex 채팅의 최근 사용자 요청·완료 보고를 대조해 정리했다. 전체 채팅 덤프나 모든 과거 첨부파일의 복제본은 아니다. 개인 AI 계정 설정·메모리·인증정보는 포함하지 않는다.

## 지금 가장 중요한 방향

최신 사용자 결정은 **사람들의 의견 모아보기와 다른 사이트의 관련 의견·반론을 보여주는 경험이 중심**이라는 것이다. 원래의 자동 팩트체크·신뢰도 점수 중심 설명으로 돌아가지 않는다. 사실과 근거 확인은 이후 보조 탭에서 제공하는 방향이다.

사용자는 의견 수렴을 8명에게 했다고 설명했다. 그 피드백을 정리하면서 사용자 평론, 공통 수집 계층과 캐싱, 여러 색으로 문장 종류를 구분하는 아이디어가 나왔다. 그러나 한꺼번에 넣으면 난잡해지고 가독성이 떨어지므로 **기능을 덧붙이며 단계적으로 발전시키라**고 명확히 요청했다. 5색의 의미나 등급은 확정되지 않았다.

현재 구현 대상으로 승인한 것은 **1단계: 문장을 누르면 관련 의견과 이유를 간결하게 보여주는 데모**다. 마지막 UI 요청은 첨부된 예시처럼 **옆에 확장 프로그램 형태로 뜨게 할 것**이었다.

## 현재 구현: festival

- 진입: `/festival.html`.
- 코드: `frontend/src/festival/main.tsx`, `style.css`.
- 축제 부스가 12개에서 8개로 줄어드는 가상 기사와 예시 의견을 사용한다.
- 오른쪽 위 S/ScrollFact 버튼으로 패널과 밑줄을 켜고 끈다.
- 네 개 밑줄 문장마다 관련 의견 2~3개, 의견별 핵심 주장과 이유를 표시한다.
- ‘원래 의견 보기’는 기사 아래 원문 발언·댓글·평론 예시로 이동한다.
- 패널을 닫고 다시 열어도 선택한 의견을 유지한다. 넓은 화면에서는 오른쪽에 고정하고 좁은 화면에서는 하단에 표시한다.
- 준비된 데이터로 동작하는 **웹 시뮬레이션**이다. 실제 AI 요약·외부 댓글 수집·사용자 평론 저장·임의 웹사이트용 확장 통합은 아직 없다.

원본 참고 HTML은 `docs/references/festival-original.html`에 보관한다. 원본에는 더 많은 기능·색상·평가가 있으나, 그 전체가 현재 승인된 구현 범위는 아니다. `festival`은 가독성을 위해 축소한 단계적 구현이다.

## 앞으로의 단계 (계획과 구현을 혼동하지 말 것)

관련 채팅에서 제안한 순서이며 1단계만 데모 구현되었다. 다음 단계를 자동으로 모두 구현하라는 상시 지시는 아니다.

1. 문장 → 관련 의견과 이유 → 원문 확인. **현재 단계.**
2. 비슷한 의견을 이유 중심으로 묶고, 공통점·차이를 요약하며 실제 의견으로 펼쳐 보기.
3. 외부 사이트의 의견·반론 연결, 출처 구분, 중복 처리. 공통 수집 계층·캐시는 기반 작업.
4. 사실·근거 보조 탭. 첫 화면은 계속 사람들의 의견.
5. 사용자의 평론·질문·수정 요청. 저장·수정·삭제·신고 같은 운영 기능도 필요.
6. 도움이 된 평론 평가와 표시 세분화. 5색은 필요와 의미를 검증한 뒤 결정.

## 왜 방향이 바뀌었나

원래 구상은 페이지 HTML을 서버에 보내 문단별 요약·신뢰도·근거·반대 주장을 스크롤로 읽는 것이었다. 긍정 점수, 음수 감점, 점수 없는 근거 리더 등 여러 실험을 했다. 사용자는 점수 차이의 의미를 설명하기 어렵고 AI가 정답을 단정하는 인상을 줄 수 있다는 멘토 피드백을 전했다. 과거 점수판은 비교용으로 남아 있으며 최신 방향의 확정안이 아니다.

또한 사실을 더 정확히 아는 것만으로 갈등이 줄어드는가에 대한 질문이 반복되었다. 특히 **사실에는 동의하지만 가치관·우선순위가 달라 갈등하는 경우**가 핵심 문제로 제기되었다. 따라서 상대가 중요하게 여기는 가치와 이유, 각 선택이 사람들에게 주는 부담, 공통점과 남은 차이를 읽도록 돕는 방향을 검토했다.

이는 아직 효과가 입증된 결과가 아니다. 실제 발언에서 확인되는 이유만 연결하고, 밝히지 않은 의도·양보 조건을 만들어내지 않는다. ‘반대 댓글 없음’을 ‘모두 동의함’으로 바꾸지 않고, 공감 수를 진실의 등급으로 취급하지 않는다. 건강한 소통을 의견 일치로 정의하지 않는다.

## AI와 백엔드의 정확한 상태

HTML gzip 업로드, 문단 파싱, 공개 출처 수집, 작업 상태·결과 조회, 취소·SQLite 저장은 구현되어 있다. `diagnostic` 모드는 AI 없이 연결을 점검한다.

실제 요약·점수 평가 제공자는 미설정이다. 기본 분석 모드는 제공자가 없으면 `503 evaluator_unconfigured`를 반환한다. `AnalysisEvaluator` 구현 또는 HTTP 어댑터가 필요하다. `SCROLLFACT_EVALUATOR_URL`은 OpenAI/Gemini 원래 API URL을 그대로 넣는 칸이 아니라 **저장소의 계약을 구현한 별도 어댑터 URL**이다.

festival 의견 수집·요약 API는 이 기존 분석 계약과 아직 통합하지 않았다. 최신 제품 방향을 구현할 때 계약·데이터 모델을 검토해야 하며 단순히 키만 넣으면 완성되는 상태가 아니다. 프론트 `VITE_*` 값에는 비밀키를 넣지 않는다.

## 실행과 이어가기

Windows PowerShell 설정과 명령은 루트 `README.md`를 따른다. 먼저 `npm ci` 후 `/festival.html`을 열어 현재 범위를 파악한다. Node.js 24.x를 기준으로 안내하며 백엔드는 JDK 17 이상이 필요하다.

일반 프론트 개발 포트는 5173, 백엔드는 8080이다. 과거 채팅의 8765 정적 서버는 자동 실행되지 않는다. `coaching.html`에 포함된 연결 점검은 8081 전용 설정이므로 일반 `/integration.html`의 8080과 구분한다. 이전 Mac의 절대 경로·실행 중 서버·로컬 DB는 새 컴퓨터에 생기지 않는다.

자료를 읽은 뒤 최신 방향과 미완료 범위를 짧게 요약하고 사용자의 다음 요청에 맞춰 작업한다. 과거 코칭 문서의 비교 시험안이나 AI의 제안을 현재 합의된 일정·검증 결과로 해석하지 않는다.

2026-11-19 Mac, Node.js 24.15.0, JDK 23.0.1에서 확인. Windows 실기 실행을 확인한 것은 아니다.
