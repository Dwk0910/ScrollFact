# ScrollFact

새 컴퓨터에서 이어서 작업하려면 먼저 [루트 실행 안내](../README.md)와 [최신 AI 인수인계](../docs/ai/HANDOFF.md)를 읽습니다. 현재 제품 방향은 의견 중심이며 아래 코칭·감점판 설명에는 과거 실험 기록도 포함되어 있습니다.

## 문장 곁의 의견 · 1단계 데모

`/festival.html`은 축제 부스 기사에서 밑줄 친 네 문장을 눌러 관련 의견과 이유를 읽는 독립 데모입니다. 각 문장은 2~3개 의견으로 연결되며, ‘원래 의견 보기’는 기사 아래의 해당 예시 발언·댓글·평론으로 이동합니다. 좁은 화면에서는 의견 패널이 하단에 열립니다. 데이터는 `src/festival/main.tsx`에 준비된 가상 예시이며, 실제 AI 분석·외부 수집·사용자 게시 기능은 없습니다. 기존 데모와 별도로 유지합니다.

`npm run build` 후 기존 정적 서버에서 `http://127.0.0.1:8765/festival.html`로 열거나, 개발 서버의 같은 경로로 확인합니다.

웹 페이지 전체의 신뢰도와 문단별 판단 근거를 보여 주는 Chrome/웨일 확장 프로그램. React + TypeScript + Vite로 만든 분석 패널입니다.

## 1:1 코칭 페이지 · 2026-11-01

`/coaching.html`에서 **코칭 한 장**과 **데모 모아보기**를 전환합니다. A4 PDF도 이 페이지에서 내려받습니다. 현재 요약은 주제 상담용으로, 원래 구상·기대 효과·대회와의 연결에 대한 의문을 담았습니다. 이전의 구체적인 사용자 시험안은 이 한 장에서 제외했습니다. 개발 서버에서는 `http://127.0.0.1:5173/coaching.html`, 현재 코칭용 정적 서버에서는 `http://127.0.0.1:8765/coaching.html`입니다.

초판(`241eaf9`의 실제 UI), 문단별 리더, 점수 없는 근거 리더, 감점형 보관본, 읽기→쓰기, 댓글 맥락/게시 전 확인, 맥락 각주, 리뷰 지도, 원문 기사, 백엔드 연결 점검까지 10개 화면을 연결했습니다. 각 화면에 시연 순서와 한계가 표시됩니다. 처음 연 화면은 계속 마운트하여 전환 시 입력·분석·스크롤 상태를 유지합니다. 「화면 새로고침」은 선택한 화면만 다시 엽니다. 기존 링크로 다른 데모를 열면 모아보기 안에서 전환됩니다.

초판은 `archive/first-edition/`에 보관했습니다. Git에 남아 있지 않은 중간 댓글 실험은 현재 통합 화면으로만 제공합니다. 초기 Vite 기본 템플릿은 제품 데모가 아니므로 제외했습니다. 코칭용 `/index.html?preview=mock`은 일반 웹에서만 샘플 모드를 강제하며 확장앱의 API 설정은 바꾸지 않습니다. AI 분석이 연결된 제품으로 제시하지 않습니다.

연결 점검의 `/integration.html?coaching=1`만 별도 **8081** 서버를 사용합니다. 일반 `/integration.html`의 기존 API 설정은 그대로입니다. 프로젝트 루트에서 다음 명령으로 다시 실행할 수 있습니다(포트가 비어 있을 때).

```bash
PORT=8081 SCROLLFACT_BIND_ADDRESS=127.0.0.1 SCROLLFACT_DB_URL=jdbc:sqlite:/tmp/scrollfact-coaching.db SCROLLFACT_CORS_ORIGINS=http://127.0.0.1:8765,http://localhost:8765,http://127.0.0.1:5173,http://localhost:5173 java -jar backend/ScrollFact/build/libs/backend-0.0.1.jar
```

정적 코칭 서버는 `frontend`에서 `npm run build` 후 프로젝트 루트에서 `python3 -m http.server 8765 --bind 127.0.0.1 --directory frontend/dist`로 실행합니다. 연결 점검 이외의 데모는 백엔드 없이 열립니다. 실제 확장앱과 원문 스크롤을 시연하려면 원문 기사를 Chrome/웨일의 새 탭에서 열고 설치된 확장앱을 사용합니다.

요약 내용의 원본은 `src/coaching/brief.json`입니다. PDF는 프로젝트 루트의 `docs/competition/build-coaching-pdf.py`로 생성하며, `output/pdf/`와 `frontend/public/coaching/`에 저장합니다. ReportLab·pypdf와 한글 지원 TTF가 필요합니다(`SCROLLFACT_PDF_FONT`로 폰트 지정 가능).

## 개발

```bash
npm ci
npm run dev -- --host 127.0.0.1 --port 5173
```

`http://127.0.0.1:5173/`에서 UI를 확인합니다. 분석 버튼을 누르면 별도 대기 화면에서 단계·경과 시간·출처 처리 건수를 보여 준 뒤 전체 신뢰도 게이지와 문단별 페이지가 나타납니다. 샘플은 약 12초 동안 진행 단계를 시연합니다. 스크롤·하단 탐색 버튼으로 이동합니다.

예상 백엔드 응답은 루트 파일 `src/sidepanel/main.tsx`의 `window.SCROLLFACT_MOCK_RESPONSE`에 있습니다. 진행 단계와 지연은 같은 파일의 `window.SCROLLFACT_MOCK_PROGRESS`에서 조절합니다. 컴포넌트별 mock은 없습니다. 콘솔에서 객체를 바꾼 뒤 다시 분석할 수도 있습니다.

## 원문 스크롤 연동

먼저 `npm run build`와 `npm run check:extension`을 실행합니다. Chrome의 `chrome://extensions` 또는 웨일의 `whale://extensions`에서 개발자 모드를 켜고 **`frontend/dist`**를 압축 해제된 확장으로 로드합니다. 이미 설치했다면 확장의 새로고침 버튼을 누릅니다. 이 빌드는 Vite 개발 서버 없이 실행됩니다.

일반 HTTP(S) 페이지에서 툴바의 확장앱 메뉴 → ScrollFact를 누르면 페이지 안에 패널이 열립니다. 브라우저의 새 탭·설정·확장앱 관리 페이지에서는 콘텐츠 스크립트가 실행되지 않습니다. 현재 패널은 페이지에 삽입한 iframe이므로 Chrome 전용 `sidePanel` 권한과 `side_panel` 등록은 사용하지 않습니다.

원문 스크롤 연동은 개발 서버의 `/demo.html`에서 ScrollFact 아이콘 → 분석 → 원문 스크롤로 확인합니다. 샘플의 CSS 선택자는 이 데모 기사의 4개 문단에 대응합니다.

변경이 적용되지 않으면 확장을 새로고침한 후 원문 페이지도 새로고침합니다. UI의 `원문 따라가기`로 자동 이동을 끌 수 있습니다. 접기는 상태를 유지하고, 닫았다 열면 새로 분석합니다.

헤더의 다운로드 아이콘으로 현재 페이지 HTML을 로컬 파일로 저장할 수 있습니다. 확장 UI와 하이라이트는 내보내기에서 제외하고, 진행 중인 원문 watch는 유지합니다. 일반 웹 미리보기에서는 미리보기 자체의 HTML을 저장합니다.

## 백엔드 연결

프론트는 원문 탭의 `document.documentElement.outerHTML`을 gzip 파일로 압축해 업로드합니다. 서버는 202로 작업을 접수하고, 프론트는 단계·출처 처리 건수와 완료 결과를 조회합니다. 원문 20 MiB/압축 5 MiB 상한을 넘으면 잘라 보내지 않고 안내합니다. 문단 분리·요약·점수·판정·이유·출처·watch 선택자는 모두 백엔드 책임입니다.

`.env.local`:

```dotenv
VITE_ANALYSIS_MODE=api
VITE_API_BASE_URL=http://localhost:8080
```

설정 후 개발 서버를 재시작합니다. 설치용 확장에서는 `npm run build` 후 확장과 원문 페이지를 새로고침해야 환경변수가 반영됩니다. 기본 mock 모드의 UI는 백엔드 없이 동작하지만, api 모드의 실제 분석에는 백엔드와 AI 제공자가 필요합니다. 자세한 계약과 이전 버전과의 기능 차이는 [API 명세](docs/backend-api.md)에 있습니다. 백엔드 실행과 AI 제공자 연결은 [백엔드 안내](../backend/ScrollFact/README.md)를 참고하세요. AI 미설정 상태에서는 실제 분석 요청에 503을 반환합니다. 상태와 결과 조회는 별도 REST 리소스입니다.

## 검증 및 배포 빌드

```bash
npm run lint
node --test tests/api.test.mjs
npm run build
npm run check:extension
```

출력 폴더는 다음과 같이 분리됩니다.

- `npm run build` → `dist`: Chrome/웨일에 설치할 독립 실행 빌드.
- `npm run dev` → `dist-dev`: HMR 개발용 확장. 해당 Vite 서버를 계속 켜 두어야 합니다.

개발 서버를 켜도 기존 `dist`를 덮어쓰지 않습니다. `check:extension`은 설치용 빌드에 개발 로더가 섞였는지, manifest와 패널이 참조하는 파일이 존재하는지 검사합니다. 다른 출력 경로는 `npm run check:extension -- /path/to/build`로 확인합니다.

`Service worker registration failed`, `unsupported MIME type ('text/html')`, `CRXJS DEV MODE`가 보이면 개발 출력물을 설치했거나 개발 로더가 잘못된 서버에 연결한 것인지 확인합니다. 특히 다른 프로젝트가 5173 포트를 사용 중이면 그 서버에서 HTML을 받아 확장이 실행되지 않을 수 있습니다. 이때 설치용 `dist`를 다시 빌드하고 확장을 새로고침합니다. 개발 서버가 필요하면 `npm run dev -- --port 5174`처럼 빈 포트를 사용합니다. [CRXJS 배포 빌드 안내](https://crxjs.dev/guide/packaging/) 참고.


## 아이디어 체험: 리뷰 지도 (Lab 03)

`/reviews.html`은 **제품이나 장소를 고를 때 서로 다른 후기를 사용 상황과 함께 비교**하는 별도 프로토타입입니다. 댓글 질문에 답하는 흐름에서 벗어나, 헤드폰 구매와 작업할 카페 선택을 체험합니다.

- 각 장면에 가상 후기 6개가 있으며, 같은 주제의 서로 다른 경험을 두 개씩 묶었습니다. 스크롤하면 현재 주제와 후기 위치가 지도에 반영됩니다. 위치 표시는 읽음/이해도/신뢰도 판정이 아닙니다.
- `안경 착용`, `주말 방문` 같은 선택 조건에 해당하는 후기를 강조합니다. 조건이 다른 후기도 숨기지 않고 함께 비교합니다. `해당 후기 보기`와 지도 주제로 직접 이동할 수 있습니다.
- 각 후기의 `후기 전문`에서 전체 원문을 펼칩니다. 비교표는 원문에 적힌 시간·환경·사용 방식을 보여주며, 확인되지 않은 정보도 별도로 표시합니다. 조건 차이가 경험 차이의 유일한 원인이라고 단정하지 않습니다.
- 좁은 화면에서는 가로 주제 지도와 본문 속 비교표를 사용합니다. 넓은 화면에서는 현재 주제의 비교표가 오른쪽에서 따라옵니다.
- 모든 가상 입력과 예상 응답은 `src/reviews/main.tsx`의 전역 `window.SCROLLFACT_REVIEW_DEMO`에 모았습니다. 실시간 후기 수집, AI 호출, 실제 쇼핑·예약, 계정 연결은 없습니다. 별점 평균은 해당 장면의 가상 후기 6개만 대상으로 계산합니다.
- 이번 실험에는 댓글 작성과 게시 전 재확인 기능이 없습니다. 기존 `/feed.html`, `/footnotes.html`과 기존 확장앱/백엔드는 비교·연속 개발을 위해 유지합니다. 새 기능을 실제 확장앱에 연결한 상태는 아닙니다.

정적 빌드의 `/reviews.html`로 실행합니다. 장면 전환이나 새로고침 시 선택 조건은 초기화됩니다.

## 아이디어 체험: 맥락 각주 (Lab 02)

앞으로 새로운 제품 방향은 직접 조작할 수 있는 데모와 함께 검토합니다. 이전 데모는 비교용 URL로 남기고, 실제 연동과 예시 데이터의 범위를 구분해 표시합니다.

`/footnotes.html`은 **현재 읽는 문장에 관련된 조건·적용 범위·미확인 정보를 연결**하는 독립 웹 프로토타입입니다. 기존 네 단계 설명창 대신 문장 곁의 짧은 각주를 사용합니다.

- 상단에서 동네 공지 / 뉴스 기사 / 커뮤니티를 전환합니다. 무료 입장의 신청 조건, 도서관 요금 조정의 적용 범위, 마인크래프트 모바일 접속의 미확인 정보를 비교합니다. 모두 가상 게시물입니다.
- 화면에 들어온 연결 대상 문장에만 각주가 나타납니다. 관련 원문이 읽기 영역에 온전히 보이면 자동 각주는 접히고, 표시를 누르면 직접 열 수 있습니다. 넓은 화면에서는 여백, 좁은 화면에서는 하단에 배치합니다.
- `원문에서 확인`으로 인용한 본문을 강조하고, `읽던 문장으로 돌아가기`로 이전 스크롤 위치와 문장 포커스를 복원합니다. 각주 스위치로 원래 페이지와 비교할 수 있습니다.
- `src/footnotes/main.tsx`의 전역 `window.SCROLLFACT_FOOTNOTES_DEMO`에 가상 본문과 예상 응답을 모았습니다. 실제 DOM에 인용문이 존재하는지 확인하며, 스크롤마다 AI를 호출하지 않습니다. 현재 연결 관계는 준비된 예시입니다.
- 새 댓글은 이 페이지의 메모리에만 추가됩니다. 새로고침/장면 전환 시 초기화되며 자유 입력 분석·게시 전 재확인은 이 실험에 포함하지 않습니다. 기존 `/feed.html`의 재확인 기능은 그대로 남아 있습니다.
- AI·백엔드·실제 SNS 연동은 없습니다. 기존 확장앱과 API 계약도 이 프로토타입으로 교체하지 않습니다.

실행은 `npm run build` 후 `dist`를 정적 HTTP 서버로 제공하거나 `npm run dev -- --port 5174` 후 `/footnotes.html`에 접속합니다.

## 읽기 → 쓰기 체험 데모

`/journey.html`은 대회 방향을 검토하기 위한 독립 웹 프로토타입입니다. 기존 확장 프로그램과 백엔드 API는 변경하지 않습니다. 실제 다른 사이트를 캡처하거나 자동으로 연결하는 기능은 아직 없으며, 두 가상 사이트를 한 화면 안에서 전환합니다.

- 첫 화면의 공지를 스크롤하면 현재 문단의 맥락 카드가 따라옵니다. 필요한 문단을 직접 담습니다.
- `의견 쓰기`로 이동한 뒤 `이 초안에 자료 연결`을 눌러 연결 대상을 지정합니다.
- 범위가 달라진 전달 / 사실을 알아도 반대하는 의견 / 자료에 답이 없는 경우, 세 가지 예시를 비교합니다.
- 초안의 표현을 선택하거나 작성창의 커서를 옮기면 해당 원문이 패널에 연결됩니다. `원문 위치에서 확인`으로 돌아갈 수 있습니다.
- 제안문은 사용자가 선택할 때만 초안에 반영됩니다. 직접 편집·유지·복사할 수 있고 자동으로 게시하지 않습니다.
- 준비된 예시와 달라진 자유 입력에는 분석 결과를 표시하지 않습니다. 실제 AI 호출과 외부 전송은 없습니다.

입력 문서와 예상 응답은 루트 `src/journey/main.tsx`의 `window.SCROLLFACT_JOURNEY_DEMO` 한 곳에서 관리합니다. 담은 문단과 초안은 브라우저 localStorage의 `scrollfact-journey-demo-v1`에 저장됩니다. 우측 상단 초기화 버튼으로 이 데모 세션만 초기화할 수 있습니다.

5173을 다른 프로젝트가 사용 중이면 `npm run dev -- --port 5174`로 실행하고 `http://127.0.0.1:5174/journey.html`을 엽니다. 빌드 결과는 `dist/journey.html`이며 정적 HTTP 서버로도 실행됩니다. 넓은 화면에서는 원문과 패널이 나란히, 작은 화면에서는 위아래로 표시됩니다.


## 피드 안에서 댓글 맥락을 연결하는 데모

`/feed.html`에서 가상 소셜 피드를 체험합니다. 현재 화면은 마인크래프트 광고 한 개에 집중합니다. 이미 달린 **모바일로 되나요?** 댓글 옆 **맥락 이어보기**로 바로 시작하거나, 같은 질문을 직접 입력해서 안내를 열 수 있습니다. 문단 담기나 자료 연결 단계는 없습니다. 이전 시장/사진 예시는 루트 데이터와 회귀 테스트에 남아 있지만 현재 화면에는 표시하지 않습니다.

- 댓글 작성, 안내 닫기/다시 켜기, 본문으로 이동, 설명 펼치기, 제안문 선택, 데모 내 댓글 게시가 동작합니다. 제안을 적용하거나 댓글을 게시하는 일은 각각 사용자가 선택합니다.
- 스크롤 중 화면에 보이는 게시물은 IntersectionObserver로 추적합니다. 댓글의 근거는 화면에서 가장 많이 보이는 글이 아니라 **해당 댓글창이 속한 게시물**에서 가져옵니다.
- `src/feed/context.ts`의 DOM 어댑터가 textarea에서 소속 article과 본문을 찾습니다. 실제 서비스에서는 이 부분을 해당 사이트의 구조에 맞게 바꿔야 합니다. 현재의 `data-sf-*` 속성은 데모 전용이며 인스타그램에 존재한다고 가정하지 않습니다.
- 모든 입력 및 예상 응답은 루트 `src/feed/main.tsx`의 `window.SCROLLFACT_FEED_DEMO`에 있습니다. 정규식으로 준비된 질문 사례를 고르는 방식이며 의미를 이해하는 AI가 아닙니다. 게시물 ID와 현재 본문의 인용문이 모두 맞아야 응답을 표시합니다.
- 입력은 메모리에만 유지하고 새로고침하면 사라집니다. AI 호출, 백엔드 전송, 실제 플랫폼 게시, 이미지 OCR은 없습니다. 참조 링크를 클릭하면 해당 외부 사이트를 엽니다.
- 기존 `/journey.html`은 이전 흐름 비교용으로 유지합니다. 기존 확장앱 분석 기능과 백엔드 계약은 이번 데모로 교체하지 않습니다.

실행: `npm run dev -- --port 5174` → `http://127.0.0.1:5174/feed.html`. 정적 빌드로는 `npm run build` 후 `dist`를 HTTP 서버로 제공합니다. 맥락 연결 회귀 검증은 `npm run test:feed`로 실행합니다. 테스트는 루트의 동일한 데이터를 읽으며 컴포넌트별 예시를 복제하지 않습니다.

### 한 댓글에서 맥락을 스크롤로 이어 읽기

이번 흐름은 **댓글 → 게시물 원문 → 추가 근거와 쉬운 설명 → 미확인 정보 → 작성창 복귀**로 구성합니다. 큰 점수나 판정을 표시하지 않고, 원문 인용·해설·정보 부족을 서로 구분합니다.

- 모달 안에서 실제 스크롤 위치에 따라 현재 단계와 연결 지도가 바뀝니다. 단계 버튼과 키보드로도 이동할 수 있습니다. 단계 표시는 읽기 위치이며 이해도나 신뢰도 점수가 아닙니다.
- `게시물의 원래 위치에서 보기`는 모달을 닫고 해당 본문을 강조합니다. 닫기/Escape/`내 댓글 그대로 돌아가기`는 초안을 바꾸거나 게시하지 않습니다.
- 다른 사람의 댓글 옆에서 시작하거나 게시 전 재확인 창에서 들어가면 **설명을 덧붙이는 답글 예시**, 자신의 질문에서 들어가면 **구체적인 질문 예시**를 보여줍니다. 제안 적용은 명시적으로 선택할 때만 이루어집니다.
- 재확인 창의 `맥락을 한 번 더 보기`가 동일한 흐름으로 연결됩니다. 돌아와도 게시가 승인된 상태로 바뀌지 않으며, 게시 버튼을 다시 누르면 현재 초안을 다시 검사합니다.
- `src/feed/main.tsx`의 전역 예시 중 `focusPostId`와 `trails`가 표시할 게시물과 설명 흐름을 지정합니다. `findTrail`은 댓글창이 속한 게시물 ID와 현재 원문 인용이 모두 일치하는지 확인합니다.
- AI 없이 준비한 설명으로 동작하는 웹 프로토타입입니다. 새 맥락 UI가 실제 SNS나 기존 확장앱에 설치된 것은 아니며, 백엔드 명세와 API도 변경하지 않습니다.

### 구현 가능성과 아직 검증하지 않은 부분

웹 확장앱의 content script는 DOM을 읽고 페이지에 UI를 추가할 수 있습니다([Chrome 공식 문서](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)). 따라서 데스크톱 브라우저에서 본문·댓글창 연결과 보조 UI를 구현할 기술적 경로는 있습니다. 이번 검증은 가상 페이지에서 수행했으며 실제 인스타그램 호환성을 검증한 것은 아닙니다. 브라우저 확장앱은 스마트폰의 인스타그램 네이티브 앱 화면 안에서 실행되지 않습니다.

실제 사이트 연동의 첫 검증 범위는 **웹 게시물 한 개 + 해당 게시물의 댓글창 하나**입니다. 이후 팝업/릴스/페이지 전환, contenteditable 입력창, 접힌 설명, 지연 로딩/가상화, DOM 변경에 대한 연결 정확도를 확인해야 합니다. 동적 삽입은 이벤트 위임/MutationObserver로 처리하고 본문을 찾지 못하면 답변을 붙이지 않는 방향이 적절합니다. 캡션이 아닌 영상·이미지에만 있는 정보는 별도 추출 없이는 다루지 못합니다.

AI 연동 시 전체 피드를 매번 업로드하기보다 선택된 게시물의 필요한 본문과 질문만 처리하도록 제안합니다. 입력 중 지연 호출, 게시물별 캐시, 초안 버전/게시물 ID 검증과 이전 요청 취소가 필요합니다. 응답에는 `postId`, `draftRevision`, `evidenceQuote`, `explanation`, `uncertainty`, `suggestedQuestion` 등을 포함하고 실제 DOM에 근거 인용문이 남아 있는지 다시 확인해야 합니다. 분석 지연 시간·오탐률·불필요한 안내 빈도·사용자의 방해 체감은 아직 측정하지 않았습니다. 입력 전송 범위와 활성화 설정은 실제 AI 연결 전에 제품 흐름으로 정해야 합니다.

마인크래프트 사례에서도 Java Edition이라는 조건만으로 모바일 접속 불가를 단정하지 않습니다. [Minecraft 공식 에디션 안내](https://www.minecraft.net/en-us/article/java-or-bedrock-edition)와 [Geyser의 교차 접속 설명](https://geysermc.org/)을 구분해 제시하며, 가상 서버가 연결 기능을 실제 지원하는지는 알 수 없다고 표시합니다.

### 게시 전 재확인 데모

`게시 전 확인창 예시`를 누르고 `게시`를 누르면 새 재확인 창을 체험할 수 있습니다. 예시 문장은 “너는 눈이 없냐? 설명 좀 읽어라.”입니다.

- 게시 버튼에서 먼저 검사하고, 재확인이 필요한 경우에는 댓글을 아직 추가하지 않습니다. 입력이 멈출 때 나오는 기존 맥락 도움말과 독립적으로 동작합니다.
- 붉은 주황색 강조선/버튼, 배경 흐림과 어둡게 처리, 한 번 확대되며 나타나는 창으로 주의를 끕니다. 반복 점멸은 없고 `prefers-reduced-motion`에서는 애니메이션을 생략합니다.
- 작성한 댓글에서 감지한 부분과 이유를 표시합니다. `수정하러 돌아가기`, 닫기, Escape는 원문을 유지한 채 작성창으로 돌아갑니다. `그대로 게시`를 선택해야 보류 중이던 댓글이 한 번 게시됩니다. 외부 플랫폼으로 보내지 않습니다.
- native dialog의 모달 동작을 사용하고, 연결된 맥락이 있으면 기본 포커스는 `맥락을 한 번 더 보기`, 없으면 수정 버튼에 놓습니다. 배경의 입력과 스크롤을 잠시 막습니다.
- 단순 질문, 반대 의견, 강한 내용 비판을 재확인 대상으로 삼지 않습니다. 루트 `src/feed/main.tsx`의 `reviewRules` / `reviewExamples`에 직접적인 비꼼·모욕·발언 억압의 일부 예시만 있습니다. 컴포넌트별 별도 목 데이터는 없습니다.
- 현재 구현은 **정해진 문장 패턴을 보여주는 데모**입니다. 모든 공격적 표현을 찾거나 인용/반어/부정 문맥을 일반적으로 이해하지 못합니다. “논쟁이 생길 확률”이나 사용자 성향을 판정하는 기능도 아닙니다. 실제 AI 도입 시에는 발언 대상, 인용 범위, 앞선 대화, 구체적 근거 구간을 함께 검토해야 합니다.
- 관련 회귀 테스트는 `npm run test:feed`에서 실행합니다. 일반 질문·반대·인용 비판의 통과와 감지 구간 보존을 함께 검증합니다.

추천 조합은 목적에 따라 나뉩니다.

1. **시연 완성도와 개발량 우선: 웹앱 + 브라우저 확장.** 원문·초안·검토 응답 구조와 UI를 공유하고, 입력/게시를 연결하는 부분만 다르게 만듭니다. 웹 데모를 실제 AI와 연결하고 확장에서는 웹사이트 한 곳만 먼저 지원하면 비교가 명확합니다.
2. **기존 모바일 서비스 활용 우선: 공유 수신 앱 + 브라우저 확장.** PC에서는 읽는 흐름 속 자동 연결, 모바일에서는 공유한 내용의 확인에 집중합니다. 모바일 앱에서 인스타그램의 게시 버튼까지 막는다고 발표하면 안 됩니다.

두 형식 모두 공통 분석부에 `sourceId`, `sourceText`, `draft`, `draftRevision`, `replyTarget`을 전달하는 구조를 제안합니다. 응답은 정보 도움말과 게시 재확인 사유를 분리하고, 인용한 근거/감지 범위를 포함합니다. 게시 재확인 기능은 각 클라이언트가 자기 게시 흐름에서 구현합니다. 이는 설계 제안이며 현재 백엔드 API를 변경한 것은 아닙니다.

실제 모바일 연동의 첫 검증은 공유받은 항목의 형태(링크뿐인지/본문 포함인지)를 기기에서 확인하는 것입니다. 입력 확보가 검증된 뒤 OCR·로그인 의존 콘텐츠 추출·AI 평가 범위를 정합니다. 공유된 URL을 받았다는 이유로 그 게시물의 모든 내용을 읽을 수 있다고 가정하지 않습니다.

공식 근거:

- [Android: 다른 앱에서 데이터 받기](https://developer.android.com/develop/ui/compose/sharing/receive) — 시스템 공유의 수신 대상과 데이터 추출.

- [Apple: 커스텀 키보드](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/CustomKeyboard.html) — 입력 주변 맥락, 앱/입력 유형 제한, 네트워크 접근 조건.

## 점수 없는 근거 리더 · 2026-11-01 멘토링 반영

`/deduction-site.html` 및 `/coaching.html#deductions`는 기사와 확장 패널의 연결 시뮬레이션입니다. `/deductions.html`은 패널 단독 보기입니다. 이전 감점 UI는 `/coaching/deduction-scoring/index.html`에 빌드 스냅샷으로 보존했고, 데모 모음에서 ‘감점형 리더 보관본’으로 열 수 있습니다. 최초 UI와 원래 양수 점수 리더도 보존합니다.

### 무엇이 달라졌는가

- 현재 수정판의 총점·문단 점수·감점 누적·가중치·신뢰 등급을 제거했습니다. 자료의 수치(40%, 조사 연도 등)와 문단 위치 번호는 원문 정보 및 탐색 용도로 유지합니다.
- ‘몇 점짜리 글인가’ 대신 **기사의 문장 → 자료 발췌 → AI 검토 의견 → 판단에 더 필요한 자료**를 보여줍니다. 같은 자료가 어디까지 설명하는지도 표시합니다. 결과를 신호등 색상이나 문서 순위로 치환하지 않습니다.
- 자료 원문이 없으면 검토할 수 없다고 표시하고, 정책적 선호는 사실 여부와 구분합니다. 자료와 맞는 부분이 있어도 문서 전체를 ‘맞는 글’로 인증하지 않습니다.
- AI 의견에는 여전히 오류나 편향이 있을 수 있음을 표시합니다. 점수를 제거한 화면이 과신이나 대인 갈등을 줄인다는 효과는 아직 검증하지 않았습니다.
- 왼쪽은 가상 언론사 ‘데일리포커스’의 기사입니다. 제호·섹션·제목·기자 정보·편집 삽화·연속된 본문으로 구성하고, 문단별 데모 페이지 같은 큰 여백을 제거했습니다. 오른쪽은 짙은 초록색 헤더와 확장 표시를 가진 별도 패널입니다. 좁은 웹 시뮬레이션에서는 패널을 더 작게 조절할 수 있습니다.

예상 백엔드 응답은 루트 `src/deductions/main.tsx`의 **`window.SCROLLFACT_EVIDENCE_DEMO`**에 모았습니다. 버전은 `evidence-prototype-2`입니다. 기존 감점용 `points`, `weightReason`, `weightNotice` 필드를 없애고, 필요한 자료(`missing`) 및 자료 발췌와 범위(`reference`)를 사용합니다. 현재는 모두 가상 기사·자료·응답이며 실제 AI 호출은 없습니다. 실제 백엔드 REST 계약과 기존 양수 리더는 이번 변경에 포함하지 않았습니다.

### 실행과 설치

1. 웹 체험: `http://127.0.0.1:8765/deduction-site.html` → **ScrollFact 열기 / 닫기** → **시연 분석 연결하기** → 기사 쪽을 스크롤합니다. 해당 문단을 강조하고 패널의 근거 검토로 자동 이동합니다.
2. **원문 따라가기 켜짐**을 눌러 자동 이동을 잠시 멈출 수 있습니다. **원문에서 보기**는 기사 위치로 돌아갑니다. 패널을 닫으면 감시·강조·여백을 해제합니다.
3. 설치 빌드: `npm run build:deductions`. 기존 설치 경로와 명령을 유지하므로 출력은 **`frontend/dist-deductions`**입니다. 내용과 표시 이름은 **‘ScrollFact · 근거 읽기 시뮬레이션’**으로 바뀌었습니다. Chrome/웨일 확장 관리 화면에서 해당 폴더를 로드하거나 기존 설치 항목을 새로고침합니다.
4. 설치형은 `http://127.0.0.1:8765/deduction-site.html?extension=1`에서 시연합니다. 이 주소에서는 웹 모사 패널을 생성하지 않습니다. 확장 아이콘 → **시연 분석 연결하기** → 기사 스크롤 순서입니다. 확장 새로고침 후에는 기사 탭도 새로고침합니다.
5. 다른 기사는 본문 아래 **다른 기사로 이어 읽기**에서 선택합니다. 이동 후 새 원문을 다시 연결합니다. URL이나 감시 중인 원문 내용이 바뀌면 기존 연결을 무효화합니다.

웹 시뮬레이터와 설치 확장은 `src/content/controller.ts`의 패널·문단 감시·강조·원문 이동 코드를 공유합니다. 통신만 전자는 같은 출처의 프레임 메시지, 후자는 Chrome runtime/tab 메시지를 사용합니다. 다른 탭·다른 스냅샷의 이벤트는 무시합니다. 본문 식별자와 실제 문장 내용이 예시 응답과 모두 일치할 때만 연결하며, 임의의 사이트에 예시 분석을 붙이지 않습니다. HTML은 로컬에서 확인하고 업로드하지 않습니다.

기본 `npm run build`는 기존 확장 동작을 유지하는 `dist`를 생성합니다. 일반 사이트의 실제 분석은 기존 백엔드/AI 연결 상태에 따르며, 이번 수정판은 준비된 기사로 읽기 경험을 검토하는 범위입니다.
